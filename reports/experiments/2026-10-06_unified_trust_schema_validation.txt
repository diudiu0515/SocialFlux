统一 trust 口径与 interaction schema：一次冻结复验

采用口径
trust 表示环境角色对具体对方在当前情境中可靠、会按所述行动的判断。
当前已发生的行为可以提供小幅可靠性证据，须指出此前具体顾虑和本轮改变。
不要求先完成未来履约；也不把所有合作、回应、承诺自动当作信任证据。
无证据或重复证据不变；有效新增证据产生方向性更新，普通/决定性只决定幅度。
数值映射、state 更新次数、appraiser 模型与推理档位均未改变。

实现与实际调用
configs/state_trust_current_evidence_v1.json 是本候选的 trust 规则单一来源。
environment/unified_appraisal.py 在实际请求中替换 trust 定义和证据规则，
延续具体评价人、被评价人绑定；标注说明也从同一文件生成。
候选工厂是 UnifiedEnvironmentFactory，不覆盖旧基线或偷偷启用正式生成。
interaction 的实际请求使用由运行时常量生成的 schema，明确 assertion_mode、
action_owner、claim impact_domains、事件/状态配对及可引用 ID。
不再依赖模型猜枚举；无效枚举和错误配对明确报告，有界格式修复全部留存。
state 与 interaction 仍读取同一更新前快照；Python 合并后只更新一次。

四个对照（调用前固定，非根据本次输出改答案）
1. 家长回答签收时间：辅导员对家长的 perceived_responsiveness 增加；trust 不强制增加。
2. 已有坦诚与安排换措辞复述：trust 不变，没有新的证据事件。
3. 家长引用辅导员已说过的承诺：不能增加辅导员对家长的 trust。
4. 同话题新披露自己的具体错误并撤回推断：trust 增加，幅度正式标签仍待核验。
确认性质：助手按用户认可口径复核既有预设，并非独立正式人工 annotation。

冻结复验
原固定十例、原预定两次复测、新增四个边界对照，共十六个 state 观测。
另外回放两条实际失败过的 interaction 请求（014、044），保留原动作和前史。
没有语义重采样；不反复运行直到通过；所有失败、格式修复、原始输出均保存。
固定输入只替换 trust 语义条目，其他上下文、初始状态、采样保持一致并做相等校验。
精确 +1/+2 不是放行条件；有无证据、对象、方向、最终更新及调用完整性分别核验。
旧脚本 strength_correct 字段是四类判断完全匹配，不是纯幅度准确率。
先跑完预定集，再检查实际理由，不能靠姓名出现或单一总通过率证明语义正确。

分项结果（按冻结标签，不等同于总体准确率）
- 原固定十例：十例最终均完整返回；目标变量识别及更新符合预设七例。
  八个新增证据正例识别六例，两个学校 trust 例仍判无证据、delta=0。
  两个原负例中，精确重复保持 0；统一标点被判 trust -1，按预设记一次误报。
- 四个边界对照：目标变量是否变化、方向与最终更新全部符合预设。
  签收回应的响应性 +1；换措辞重复 trust 0；引用他人承诺 trust 0；新自我纠错 trust +2。
  这些是协议预设经助手复核，不冒充独立正式人工标签。
- 两次预定复测：坦诚 +1、重复 0，均符合有无更新预设。
  坦诚原次与复测实际请求完全相同，均强度 1、trust 5→6，不涉及 0/10 裁剪。
- 强度另计：原十例四类判断完全匹配六例；坦诚判普通而参考标签为决定性，
  但其新增证据与 +1 方向正确，不因此判更新失败。新纠错判决定性 +2，参考为普通，
  同样只记强度分歧，不作为放行失败理由。
- 调用完整性：十六个 state 逻辑观测及两个 interaction 回归均最终完整返回。
  两个 interaction 均首次 schema 通过，无格式修复。
  state 第七号安全感减少样例有一次格式修复：原答 direction 使用 up/down，
  而接口要求 increase/decrease。该原答同时误读了说服董事会的责任归属，
  最终接受答案已正确归属于领导。原答、错误原因和修复后答案全部保留。
  不把修复后的正确结果说成每次原始回答都正确；未截断转空、未语义重采样。
- 最终关系变量理由经逐例检查，未见明显评价人/被评价人反转；这不是普遍可靠性的证明。
  学校已知反转对照已正确解释为辅导员评价家长，不是家长评价辅导员。

仍需裁定的具体边界（不改本轮标签）
1. 学校两例：既定人工标签认为当前行为提供家长可靠性的普通证据；模型承认回应性、
   程序边界改变，却认为没有具体可靠性顾虑被改变。不是候选已识别后被校准器拦截。
   完整前史、初始化依据和原答均在对应案例目录，不把当前争议归因于某一个未经对照的因素。
2. 标点负例：编辑刚问“完全不提，还是标注为待核实的说法？”，记者答
   “我先把稿件里的全角标点统一一下。”模型将暂时转题推断为可靠性下降。
   按调用前标签仍记误报；这一前史也说明该负例不是脱离上下文的绝对无关句。
   不能因看到模型理由就把目标答案改成 -1，也不能把这种分歧藏在总分里。
3. 强度与首次格式输出仍有限制：坦诚 +1/+1 稳定不证明强度普遍校准；
   state 原答仍发生一次方向枚举错误与局部事实归属误读，修复记录不能删除。
